# 每日推荐 · 历史行点击弹窗 — 设计规格

- 日期：2026-09-01
- 状态：交互方案已批准；规格经三转自审，待总司令终审
- 前置：每日推荐系统 v1（`docs/superpowers/specs/2026-08-31-daily-betting-advisor-design.md` §前端）

## 1. 需求

「每日推荐」页签底部战绩历史表，点击任一历史行，弹窗展示**当时那一批模拟票**的完整明细（含每场判定结果）。

决策记录（头脑风暴确认）：
- 弹窗形态：**复用票卡 + 汇总头**（观感与今日区完全一致）
- 休战行/待结算行：**统一可点**（休战弹窗展示休战文案块；待结算票卡显示"待赛"状态）
- 赔率即下单时固化在票上的值，无盘口历史概念——"当时的票"天然吻合

## 2. 交互规格

| 项 | 规格 |
|----|------|
| 可点区域 | 历史表全部数据行（含 `tr.rest`）；表头行不可点 |
| 可点暗示 | 行 hover 背景变色 + `cursor:pointer` |
| 弹窗打开 | 动态创建遮罩 + 内容容器（仿 `schedule.js showMatchModal()` 惯例，遮罩层级与 match-modal 同 z-index）；打开时 `body.style.overflow='hidden'` 锁滚动，关闭还原 |
| 小屏适配 | 弹窗容器 `max-height:85vh; overflow-y:auto`，票多/窄屏时可滚，不撑破视口 |
| 弹窗关闭 | 右上 ✕ / 点击遮罩 / ESC，三种方式行为一致；关闭后解锁滚动 |
| 重复打开 | 先关闭已有弹窗再开新窗（与比赛详情弹窗同规则） |

## 3. 弹窗内容

```
┌─ 2026-08-31 · 2张票 · 投入¥6 · 盈亏+¥2.14 ─┐
│ [票卡 ×N —— 直接复用 ticketHtml()]          │
│ （每场：联赛 · 对阵 选项@赔率 开球 · ✓/✗比分）│
│                                   [✕]      │
└────────────────────────────────────────────┘
```

- 汇总头按日型三分支：
  - 已结算：`{date} · {N}张票 · 投入¥{Σstake(不含void票)} · 盈亏±{Σpayout−Σstake}`（与 `historyHtml()` 行内同一套算式/抽公共函数，保证弹窗数字与被点的行完全一致）
  - 未全结算：末段显示 `待结算`（盈亏数值不显示）
  - 休战：`{date} · 休战`，主体直接复用 `t('adviceRest')` 休战文案块（与今日区同一 i18n key，不新增、不另写文案）
- 票卡：`tk.legs.map` 及 `combinedOdds/payout/result` 全部走现有 `ticketHtml()`，不复制粘贴渲染逻辑
- 口径背景（2026-09-01 总司令裁决）：原"7 天自动作废+退本"机制废除（长期查无赛果的票保持 pending 不计统计，由总司令人工判定后结算，详见口径修订规格）。现存数据无 void 票，弹窗按"与被点行完全一致"原则继承行算式即可；开球超 7 天仍未回收的票，票卡判定位显示"**待判定**"（前端由 `kickoff` 推算，与 `ticketHtml()` 现状改造同批实施）

## 4. 数据流

- `renderAdvice()` fetch 成功后将 `d.days` 存入模块级缓存 `adviceDaysCache`
- `historyHtml()` 生成行时输出 `data-date="{date}"`（表头行不加，天然不可点）
- 点击：事件委托绑在**常驻容器** `#advice-content`（index.html:73，已核实存在）上，`e.target.closest('tr[data-date]')` 命中即开弹窗 → 由 `data-date` 在缓存中查 day → 渲染
- **绑定且仅绑定一次**：`renderAdvice()` 会被语言切换/页签刷新反复调用，监听用模块级 flag（如 `adviceHistBound`）守卫，防止 handler 堆积
- 零新增网络请求；弹窗数据永远与当次页面加载的 JSON 一致

## 5. 代码触点

| 文件 | 改动 |
|------|------|
| `js/daily-advice.js` | days 缓存、行加 `data-date`、容器委托监听、`openAdviceDayModal(dateStr)`、`closeAdviceDayModal()`、`adviceModalHtml(day)` |
| `css/style.css` | `.advice-modal-*` 遮罩/容器/汇总头/关闭按钮样式，骨架仿现有 match-modal |
| `index.html` | 无改动 |

预估 ~60 行增量。不新建 JS 文件（体量不值得拆分，保持 daily-advice.js 单一职责域）。

## 6. 文案纪律（大白话铁律）

- 允许：场 / 票 / 张 / 投入 / 盈亏 / 命中 / 待赛 / 休战
- 禁止：腿 / ROI / 串关术语堆砌（票卡现有 `2串1` 标签为既定产品命名，保留）
- 弹窗文案中文直写（与历史表现状一致；英文模式随 Figma 视觉稿统一改造，本次不动 i18n key）

## 7. 边界与错误处理

| 场景 | 行为 |
|------|------|
| day 在缓存中查无（理论不发生） | 点击无效果，不弹错 |
| `tickets` 为空但 `rest!==true`（脏数据） | 按休战分支兜底显示 |
| 票/场次字段缺失（老 JSON） | 对应位显示 `—`，禁止 undefined 上屏 |
| fetch 失败历史表未渲染 | 无点击面，天然安全 |

## 8. 不变量（引擎侧）

本特性纯前端只读，不触碰 `data/daily-advice.json` 写路径、不影响计划任务与引擎幂等。
