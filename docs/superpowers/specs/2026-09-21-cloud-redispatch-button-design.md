# 云端补出按钮 + 长期双窗口 — 设计规格

- 日期：2026-09-21
- 状态：五节设计已获总司令批准；规格待终审
- 前置：每日推荐系统 v1（`docs/superpowers/specs/2026-08-31-daily-betting-advisor-design.md`）；Gitee Go 云通道计划（`projectDoc/plan/2026-09-04-gitee-go-shadow-channel.md` §九 B 案）
- 语境：09-17 / 09-19 / 09-20 三连云端异常（clone_fail / push_fail），09-12 与 09-19 因「云失败 + 本机未开机」双哑**永久缺票**

## 1. 需求与决策记录

**痛点**：苏州→GitHub 链路坏时段集中在上午（09-11 实证 11:34~11:42 五连败、下午自愈）；本机 12:45 兜底依赖机器开机，周末/节假日不成立。二者叠加即缺票。

**总司令诉求**：① 长期双窗口（云 11:30 + 13:30），不因网络原因缺票；② 网页界面加按钮，人工补出。

**头脑风暴决策**：

| 议题 | 决策 |
|---|---|
| 按钮语义 | **只补不覆盖**——当日无票时补出；已有票则不动账本（引擎默认即幂等补出语义） |
| 防滥用 | **口令 + 每日限次**（口令存 Worker 环境变量，不进前端代码） |
| 双窗口额度 | **压缩重试 + 额度哨兵**（失败班 15~17 分压到约 9~10 分；哨兵报警请令） |
| 补出范围 | **只补当日**，Worker 不接受日期参数 |
| 触发路径 | **方案 A：CF Worker 中继 + push 触发云班**（机制已实证：09-08 / 09-11 / 09-20 的班次即 push 触发；`PROBE.md` 现内容 `trigger probe 1329` 即探针文件） |

## 2. 非目标（YAGNI）

- **不做**「覆盖重出」：不碰 `--regen` / `--force`，不引入覆盖当日已出票的能力（会丢已结算盈亏、破坏账本「只追加」）
- **不做**历史日期补出：与 09-19「永久缺票，不补跑」定案一致；云端 `shadow.sh` 本身只处理当日
- **不做**额度自动回退：改云端 cron 只能总司令在 Gitee 网页编辑器保存才生效（git push 不重注册，09-08 实锤）——哨兵只能报警
- **不改**引擎 `scripts/daily-advisor.js`；**不改**数据结构与 API 接口（纯加触发层与 UI）
- **不做**账号体系 / 多用户 / 操作审计

**实施分期（两阶段交付，各自独立可验）**

| 阶段 | 内容 | 前置 | 风险 |
|---|---|---|---|
| **阶段 1** | 长期双窗口（cron 网页保存）+ `shadow.sh` retry 压缩 + 额度哨兵 | 仅总司令网页改 cron | 低——当班即可验 |
| **阶段 2** | CF Worker + 前端补出按钮（含口令与限次） | Gitee 令牌写入权限 PoC 通过 | 中——依赖未验的令牌 scope |

## 3. 架构

```
[每日推荐页签 · 补出按钮]
   │ POST {pass}（HTTPS）
   ▼
[CF Worker: shadow-trigger]   env: DISPATCH_PASS / GITEE_TOKEN / KV: DISPATCH_KV
   │ ① 常数时间比口令 ② KV 记「北京日」触发次数（上限 3）
   │ ③ Gitee API 改写 shadow 库 PROBE.md
   ▼
[Gitee 私密库 gao-jiashun/shadow · master]
   │ yml `triggers.trigger: push` → 起班
   ▼
[shadow.sh · MODE=issue]
   selftest(31 用例) → `node scripts/daily-advisor.js`（零改动，默认幂等补出）
   ▼
有 diff → pull+push GitHub main（commit 标 [cloud-primary]）
无 diff → RESULT=no_change
   │ 两路都写 status 分支留档
   ▼
[GH Pages / CF Pages 构建] → data/daily-advice.json 更新 → 前端轮询看到新票
```

**新增 3 件**：Worker `shadow-trigger`、前端按钮、额度哨兵。
**改动 2 件**：`shadow.yml` 的 cron（总司令网页保存）、`shadow.sh` 的 retry 次数。

## 4. 组件与接口

| 组件 | 接口 | 规格 |
|---|---|---|
| 前端按钮 | `adviceDispatch(pass)` → `POST https://<worker>/dispatch` | 可用条件见下表（按当日批次状态三态判定） |
| Worker `GET /` | 健康检查 | 返回 `{ok, day, used}`；不含任何敏感值 |
| Worker `POST /dispatch` | body `{pass}` | 成功 `{ok:true}`；口令错 `401`；超限 `429` |
| Worker → Gitee | `PUT /api/v5/repos/gao-jiashun/shadow/contents/PROBE.md` | 先 GET 取当前 `sha` → base64 写入 `trigger probe HHMM manual` → message `chore: manual dispatch` |
| 额度哨兵 | 每月 1 号 + 16 号核账 | 按 quota-peek 口径算三线占用；>80% 报警请令 |
| `shadow.sh` 压缩 | `retry 5` → `retry 3` | 两处：clone 段、回写段（status 分支 `retry 3` 不动） |

**按钮可用性三态（判定依据：`days` 末条是否等于北京今日）**

| 当日状态 | 判定 | 按钮 | 文案 |
|---|---|---|---|
| 无当日批次（云与本机都哑） | `days` 末条 ≠ 今日 | **可用** | 「今日暂无批次 · 补出」 |
| 有当日批次、0 票（休战） | 末条 = 今日 且 `rest === true` | **可用**（休战可能因取数失败误判） | 「引擎判定休战，补出也不会出票 · 仍要补出」 |
| 有当日批次、有票 | 末条 = 今日 且 `tickets.length > 0` | **禁用** | 「今日已出 N 张」 |

**口令与限次细节**
- `DISPATCH_PASS`：Worker 环境变量；前端首次点击弹输入框，存 `localStorage.advice_dispatch_pass`，后续免输
- 限次键 `d:<北京日>`（与引擎 `day.date` 同口径），上限 **3 次/日**
- 口令错：独立冷却键 `f:<客户端IP>`，60 秒内拒绝；**不计入**每日触发次数
- 口令轮换：只改 Worker 环境变量，前端无需改动

**按钮文案（禁行话，遵项目 UI 口径）**
- 可点：「今日暂无票 · 补出」
- 进行中：「已受理 · 云端处理中，约 5~10 分钟」（Task 5 PoC 实测：起班排队可慢至 9 分钟）
- 休战日仍可点，但先显示说明：「引擎判定休战，补出也不会出票」

## 5. 数据流

1. 点按钮 → 首次弹口令 → 存 localStorage
2. Worker：比口令 → KV 计数 +1 → 写 `PROBE.md` → 返回 `{ok:true}`
3. 按钮转「已受理」，前端**每 30 秒**重拉 `data/daily-advice.json?_=<ts>`（复用现有 `adviceFetch()`，已带 cache-bust），最多 **20 分钟**
4. 出现当日票 → 提示「已补出」并重渲染；超时 → 提示「未检测到，请稍后手动刷新，或查看哨兵/status 记录」

⚠️ **已知 UX 偏差（必须写进文案）**：轮询延迟 = **流水线排队（1~9 分钟，Task 5 PoC 实测最长约 9 分钟）+ 云班执行（2~5 分钟）+ Pages 构建（1~2 分钟）**，最坏可近 15 分钟。**「等得久」≠「按钮没生效」**，否则会被误判为故障。

## 6. 异常与降级

| 情形 | 表现 | 处理 |
|---|---|---|
| 口令错 | `401` | 提示重输；60 秒冷却；不计触发次数 |
| 当日已有票时误点 | 云班 `no_change` 空转 | 前端已禁用按钮；万一绕过，仅烧额度、不动账本 |
| 引擎判休战 | 补出后仍 0 票 | 按钮文案预先说明；点后可看 status 留档 |
| 云班失败（clone_fail / push_fail） | 前端只知「已触发」 | 提示查 status 分支 / 等哨兵汇报；可在限次内再点 |
| Gitee 令牌失效或权限不足 | `502` | 提示「云端触发失败，报总司令」；轮换只改 Worker env |
| 额度耗尽（>500 分/月） | 按钮永久失败、云通道停跑 | 额度哨兵提前报警；回退单窗口由总司令网页改 cron |
| Worker 不可用 | 请求超时 | 前端提示「触发通道不可用，请走本机兜底/次日核实」 |

## 7. 双窗口与重试压缩

| 项 | 内容 |
|---|---|
| cron | `'0 30 11 * * ?'` → **`'0 30 11,13 * * ?'`**（仍一条，Quartz 小时位逗号列表） |
| 唯一入口 | 🔴 总司令 Gitee 网页编辑器保存（git push 不重注册）。坑纪律：报 `cronExpressionError` → 空内容再保存复活；确认无报错弹窗（报错但内容相同 = 假绿） |
| 跑班逻辑 | 11:30 主出票；13:30 补班——已成功则 `no_change` 空转 |
| 与本机 12:45 关系 | 照旧；机器在线则 12:45 先补、13:30 空转；**机器离线时 13:30 为救命班** |
| 与按钮关系 | 三层保险：双窗口（自动）+ 本机兜底（半自动）+ 按钮（人工） |
| 额度实测 | 当月（09-07~09-21）**182.7 分 / 500（36.5%）**，23 班次；单班均值 7.9 分，健康班 6.1 分，失败班 9.9~15.3 分 |
| 额度预测 | 双窗口满月 **222~534 分（44%~107%）**；压缩重试后预计回落到 **300~400 分（60%~80%）** |
| 回滚 | 网页改回单窗口 cron；期间本机 12:45 不断粮，无业务风险 |

**额度哨兵分级**：🟢 <50% ｜ 🟡 50~80%（提示收敛推送、合并提交） ｜ 🔴 >80%（请令回退单窗口）。

3. 连点 4 次 → 第 4 次 `429` — ⏳ 待 Task 7
4. 🟡 **部分已验（09-21 浏览器实测）**：三态渲染全部正确（休战「引擎判定休战 · 仍要补出」金色可点／有票「今日已出 1 张」灰色禁用／无批次「今日暂无批次 · 补出」）；点击链路通（发出 `POST /dispatch`，Worker 未部署故 `ERR_CONNECTION_REFUSED`，catch 分支显示「触发通道不可用 · 重试」后 4 秒复原）。**「受理 → 轮询 → 刷新出票」全链未验**，待 Task 7 + Task 9

**待自然场景验（显式未验，不得假称已验）**

5. **真补出路径**：需要一个「当日无票」的当天才能端到端验证——今日（09-21）已出休战批次，只能先验**幂等空转 `no_change`** 路径；真出票路径等下次自然缺票日观察并补记
6. **双窗口**：cron 改后观察当日 13:30 班 `no_change`（当日 md 只留最后一班，取证看 status 分支 git 历史）
7. **retry 压缩效果**：观察下一个失败班时长是否由 15~17 分降至约 9~10 分
8. **轮询实际延迟**：实测「云班时长 + Pages 构建时长」是否落在 10 分钟窗口内

## 9. 不变量与铁律

- 引擎 `scripts/daily-advisor.js` **零改动**；账本**只追加**；去重键 `matchId|pool` 跨日；`day.date` = 北京生成日
- 数据结构与 API 接口不变（本设计纯加触发层与 UI）
- 密钥纪律：Gitee 令牌与口令**只存 Worker 环境变量**，不进前端代码、不进规格/文档、不进仓库
- 不自动 commit / 不自动 push；每次提交与推送均等总司令令
- 哨兵与额度哨兵均**只读 + 只报告**，不代写文档、不自动改配置

## 10. 风险与未决

| 风险 | 影响 | 缓解 |
|---|---|---|
| Gitee 令牌 scope 不含 `projects` | 方案 A 路堵 | 首个 PoC 验证；不可用则退「令牌新建专用 scope」或改走 B 案 API |
| 口令泄露 | 额度被刷 | 每日限次 3 次兜底；口令可随时轮换 |
| 双窗口月度触线 | 云端停跑，比现状更险 | retry 压缩 + 月度额度哨兵报警 |
| Pages 构建延迟 | 轮询误判为失败 | 文案明示；超时提示引导查 status |
| `PROBE.md` 假提交堆积 | Gitee 库噪声 | 每次覆盖同一文件，仅留一条历史；可定期清理 |
| 观察期 10-15 收官后体系去留未定 | 长期双窗口的前提可能消失 | 哨兵 10-11 检查点已挂；届时一并裁决 |
