## 一、目标与原则

- **目标**：云端为主，「当日必出票」彻底不依赖本机在线；本机降为兜底，云断则补位。
- **原则（v2 军规）**：
  1. 云 Gitee Go 每日 **11:30**（北京）主出票，commit 标 `[cloud-primary]`；
  2. 本机计划任务 `DailyBettingAdvisor` 改 **12:45**：pull 后预检「当日批次已存在→待命退出」，无批次才顶跑，commit 标 `[local-backstop]`；
  3. **引擎零改动**：幂等键 `matchId|pool` + `day.date`=北京生成日 + 无变化跳过——谁先写入谁得当日档案，另一方自动空转；
  4. 令牌只存私密 shadow 库根 `config.sh`（平台会洗 yml `variables:` 值，09-07 实锤）；GitHub PAT 30 天过期，Gitee 令牌季度手动轮换（进过 git 历史/日志即视为泄露面——09-11 事件实证，见 §八）。

## 二、架构

```
Gitee Go（百度云苏州）yml triggers.schedule cron '0 30 11 * * ?'（**6 段 Quartz 秒分时日月周**；社区版定时写在 yml，仅一条；「定时运行」表单是企业版功能）
  └─ gao-jiashun/shadow(私密) .workflow/shadow.yml   # 密钥走根目录 config.sh；master push 亦自动触发（白捡验证）
       └─ shadow.sh（仓库根）:
            1) clone GitHub 公开库 --depth=1（重试×5，治苏州→GitHub 抖动）
            2) node scripts/daily-advisor.js --selftest —— 两模式共用闸门
            3) SHADOW_MODE=issue：无参跑引擎（回收+出票）→ daily-advice.json 有 diff 才
               commit "[cloud-primary]" → pull --rebase → push GitHub main（重试×5）
            4) 无论成败：执行摘要回写本库 status 分支（每日一 md，日志需登录方可看）
本机 12:45：run-daily-advisor.ps1 → 预检 → 无当日批次才顶跑 [local-backstop]
```

- 产物镜像：本仓库 `shadow/shadow.sh` + `shadow/shadow.yml`（占位符模板、无密钥）；**source of truth = Gitee 私密库**。
- 已知代价：Gitee Go 免费档无 SLA，漏跑/延迟时批次漂到 ~12:45 本机补位；极端竞态（云迟写撞本机批次）由 rebase 冲突自动败者退让，不脏数据。
- 免费额度：每日 1 跑约 3-5 分钟，月耗 ~120 分钟 < 500 分钟个人月额。

- **根因链**：`cron '30 11 * * *'`（5 段 POSIX，官方文档示例样式）被平台**静默忽略、定时从未注册**；后探明 Gitee Go 真格式为 **6 段 Quartz `秒 分 时 日 月 周`（周位 `?`）**——`'30 11 * * ?'` 报 `YamlConvertException.cronExpressionError`，`'0 55 13 * * ?'` 通过。

- **实锤**：15:07:45 #9 构建历史标注「**定时触发**」自动起跑；当日票未缺——12:45 本机保险丝顶跑 `[local-backstop]`（M4 断云演练同日意外完成）。

### 根因与经验沉淀

1. **泄露路径**：`retry()` 失败时 `say "retry ... failed: $*"` 记录命令全文，而命令内嵌 `$GH_PUSH`（`https://user:PAT@github.com/...`）。教训：**任何可能记录命令行全文的日志，必须在唯一写出口统一脱敏**——修在 `say()` 而非各调用点，覆盖未来新增。
2. **push_fail 根因未终锤**：特征符合苏州→GitHub 半死链路（STALL 掐断），完整日志需 Gitee 网页端登录查；不影响业务定性（兜底已补位）。
3. **dry-run 验证法**：`git push --dry-run` 走 receive-pack 写服务，握手即鉴权+校验推送权限（无效令牌报 Authentication failed、只读令牌报 403），可零副作用实锤写权限；443 被重置属墙况波动，重试即可。
4. **push 触发器白捡验证**：yml 本配 master push 触发——每次推送 config.sh/shadow.sh 自动获得一轮云端验证（幂等 no_change 空转），可省手动触发；代价每轮 ~6-7 分钟 Gitee Go 额度。
5. **轮换时序军规定稿**：发新令牌 → 改 config.sh 推送（自动触发验证）→ dry-run 实锤 → **实锤通过后才吊销旧令牌**；全程避开 11:25~11:45 云端定时窗口。下次轮换四步流程已写入提醒任务 `b60add57`（10-05 09:55）。
