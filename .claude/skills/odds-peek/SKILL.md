# 复看当下赔率（只读 peek）

## 这个技能解决什么

「每日推荐」引擎每天北京 **11:30** 由本机计划任务跑一次、锁定一批模拟票并如实记录盈亏。但体彩赔率全天在变（9–11 点变盘高峰、11:00 开售、临场趋稳）。总司令有时想在**任意时刻**知道"现在盘口如何、此刻引擎会选谁、会不会出票"——但要**纯参考**，绝不能污染那条"当日快照如实记录"的战绩档案。

`--peek` 正是为此：**复用与正式出票完全相同**的取数→白名单过滤→黄金/彩蛋候选→配对逻辑，但**只打印、绝不 `writeDataAtomic`**，也不碰 `days`/`summary`/计划任务。所以随时复看都不会改变任何已记录的东西。

## 怎么做

在仓库根（`E:\GitHub\WorldCup2026`）执行：

```bash
node scripts/daily-advisor.js --peek
```

脚本路径自带 `__dirname` 解析 `data/daily-advice.json`（只读），故从任意 cwd 跑都行；但请**从仓库根**跑以免混淆。它现抓 sporttery（本机为国内 IP，通道通）。约 1–3 秒返回。

> 这是**唯一**该跑的命令。不要加 `--regen`/`--force`（那会真正改写当日批次），不要无参跑（那会走计划任务的出票/结算/写盘路径）。看到"复看/盯盘"类意图 → 只跑 `--peek`。

## 怎么读输出

典型输出：

```
[只读复看·不写盘] 北京时间 15:40 | 在售20 -> 白名单窗口内2 -> 黄金候选0 彩蛋候选0
若此刻出票 -> 休战(零候选)
（仅供参考：未写入 daily-advice.json，不影响计划任务）
```

**漏斗三段**是诊断关键，逐段判读：

| 信号 | 含义 | 结论 |
|---|---|---|
| `在售0` | sporttery 返回空 / WAF 拦 / 网络 | **不是"没票"，是"没抓到数据"**——提示可能通道问题，别误判 |
| `白名单窗口内0` | 抓到了，但 3–36h 内无英超/西甲/意甲/德甲/法甲/欧冠/欧罗巴在售 | 赛程空窗（如国际比赛日/休赛期）→ 正常休战 |
| `黄金候选0 彩蛋候选0` | 有场次，但开盘价都不在黄金区间 [1.30,1.60] / 无 ±2 让球彩蛋 | 数据健康，只是当下没有值得下注的价位 → 正常休战 |
| 候选 > 0 | 下面会逐条列出，并给"若此刻出票" | 把票面如实呈现 |

出现候选明细行时（黄金#/彩蛋#），每条含：联赛、对阵、方向@赔率、(边缘)、开赛时间。`若此刻出票` 行给出配对后的票（2串1 或单关），与 11:30 正式批次同算法。

## 汇报格式

用总司令的军事化汇报结构——**先结论、再数据、后边界**：

```
**复看 @ <北京时间>**：<一句话结论：休战 / 或 N 张候选票>
- 漏斗：在售 X → 白名单 Y → 黄金 Z / 彩蛋 W
- <若有候选>票面：<kind> <对阵> <方向>@<赔率> …
- 与 11:30 已锁定批次对比：<是否一致 / 今日已休战 / 今日已出票 X 张不受影响>
- 边界：只读，未写盘、未动计划任务（可附 daily-advice.json 哈希前后一致为证）。
```

## 安全与边界（务必守住）

- **只读**：`--peek` 结构上不写文件。若需向总司令自证，可比对哈希：`git hash-object data/daily-advice.json`（跑前/跑后应相同）。
- **不改记录、不动任务**：peek 不产生提交、不改 `days`；计划任务仍按 11:30 自己跑它的正式批次。
- **不提交**：这条命令及其输出与 git 无关；除非总司令另有指令，不要因此提交任何东西。
- **时效语义**：越早复看，赔率越"毛"（未过变盘高峰）；把这点讲清楚，别让总司令把一次临时 peek 当成"官方当日结论"。官方结论永远是 11:30 那条。
- **数据口径**：白名单联赛是**欧洲俱乐部赛事**，与已冻结的世界杯 WCC 赔率文件（`data/lottery-odds.json`）无关——别把两者混为一谈。

## 失败处理

- 打印 `PEEK FAIL: ...` 或非零退出：多为网络/超时/接口异常。**只读命令，出错也无副作用**；向总司令复述错误行，建议隔几分钟重试或检查本机出口，切勿改用会写盘的命令来"绕过"。
- `在售0`：先怀疑通道（WAF/网络）而非"真没比赛"；可与"白名单窗口内"是否为 0 交叉判断——若在售>0 只是白名单 0，则是赛程空窗，属正常。
